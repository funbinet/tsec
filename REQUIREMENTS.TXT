# TSEC — external requirements
#
# Every binary the framework launches is listed here with the Arch package that
# provides it and the release whose help output the catalog was verified
# against. The framework refuses to offer a capability whose tool is missing or
# whose flags are not documented by the installed version, so this file is the
# single place that says "install these to get the full toolset".
#
# ONE REQUIREMENT IS NOT A TOOL
#
#   oniux   the network-execution boundary; see below.
#
# Every other entry is optional in the sense that TSEC still starts without it —
# the affected capabilities simply report themselves unavailable, with a reason.
# oniux is different: without it, no network-capable task can run at all.

# ── The network boundary ──────────────────────────────────────────────────────
# oniux is the required Linux network-execution boundary. The framework launches
# every network-capable command as `oniux <tool> <args…>`, inside a private
# network/mount/PID/user namespace whose only route is an embedded Tor (Arti)
# client. There is no SOCKS endpoint to configure, no proxy flag to set, and no
# in-framework switch to turn it off: Tor and oniux are configured and
# supervised by the operating system, and the framework's job is only to
# guarantee that nothing reaches the network except through them.
#
#   Arch (AUR):   paru -S oniux          (or: yay -S oniux)
#   from source:  cargo install --git https://gitlab.torproject.org/tpo/core/oniux --tag v0.4.0 oniux
#
# The framework is written against oniux v0.4.0, whose entire CLI is
# `oniux [command] [args...]` — it takes no options, so TSEC injects none.
#
# oniux needs:
#   * the `tun` kernel module:            sudo modprobe tun
#   * unprivileged user namespaces, and on distributions that restrict them:
#       kernel.unprivileged_userns_clone = 1
#       kernel.apparmor_restrict_unprivileged_userns = 0
# Verify with:  oniux /bin/true   — silence and a zero exit code means the
# boundary works; the framework runs this same probe automatically before the
# first network task.
#
# Verify from TSEC:  tsec doctor        (or just run tsec and read the
# BOUNDARY line in the startup output).
