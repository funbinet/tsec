# TSEC 3.0 — external requirements
#
# TSEC 3.0 ships one mandatory dependency and a large set of optional provider
# tools. The optional ones are genuinely optional: a capability whose providers
# are missing is still listed, is reported unavailable with the missing binary
# named, and is never substituted. The mandatory one is not a tool.
#
# ── The network boundary: oniux ──────────────────────────────────────────────
#
# oniux is the required Linux network-execution boundary. Every network-capable
# command is launched as `oniux <tool> <args…>` inside a private network, mount,
# PID and user namespace whose only route is an embedded Tor (Arti) client.
# There is no SOCKS endpoint to configure, no proxy flag to set, and no switch
# in the framework or in the configuration file that turns it off. Tor and oniux
# are configured and supervised by the operating system; the framework's only
# responsibility is to guarantee that nothing else reaches the network.
#
#   Arch (AUR):   paru -S oniux          (or: yay -S oniux)
#   from source:  cargo install --git https://gitlab.torproject.org/tpo/core/oniux --tag v0.4.0 oniux
#
# TSEC is written against oniux v0.4.0, whose entire CLI is
# `oniux [command] [args...]` — it takes no options, so none is ever injected.
#
# oniux needs:
#   * the `tun` kernel module:            sudo modprobe tun
#   * unprivileged user namespaces, and on distributions that restrict them:
#       kernel.unprivileged_userns_clone = 1
#       kernel.apparmor_restrict_unprivileged_userns = 0
#
# Verify the boundary on its own:  oniux /bin/true
# Silence and a zero exit code means it works. TSEC runs this same probe before
# the first network task of a run, and reports the result in `tsec --status`.
#
# ── Provider tools ───────────────────────────────────────────────────────────
#
# The list below is the common toolset, in the form:
#
#     binary            Arch package            purpose
#
# Package names are for Arch; other distributions package the same upstream
# tools under similar names. Versions are deliberately not pinned: the catalog
# names the exact argument vector an operation runs, and a tool whose CLI has
# changed fails loudly, with its own message in raw/<artifact>.err and in the
# run manifest, rather than being worked around silently.

#   `tools.search_paths` in config.toml; those directories are searched before
#   PATH, in order.
